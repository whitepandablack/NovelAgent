# NovelAgent v0.2 长篇创作工作台设计

## 目标

把 NovelAgent 从一次性 MVP 种子生成器升级为本地优先的长篇小说创作工作台。系统底层保留可测试、可审计的 workflow，对外通过 CLI 提供连续写作入口，并为后续真正的 agent 调度层和 LLM 接入预留稳定接口。

## 范围

v0.2 同时覆盖长篇创作引擎和作家工作台 CLI：

1. 保存世界规则、线索、时间线事件、章节计划、修订任务等结构化记忆。
2. 支持根据项目状态规划下一章。
3. 支持根据章节计划起草下一章。
4. 支持对章节执行更完整的连续性审稿。
5. 支持把审稿问题转成修订任务，并生成修订版章节。
6. 支持通过 CLI 查看状态、规划、起草、审稿、修订和导出正文。

v0.2 不强制接入真实 LLM。所有生成逻辑保持确定性，确保本地测试稳定。LLM provider 后续作为生成器接口的实现替换，而不是改写项目数据结构。

## 架构

系统分为三层：

- `NovelProject`：项目状态容器和 JSON 持久化边界，负责保存所有可审计结构化字段。
- `NovelWorkflow`：稳定执行创作步骤，包括 seed、规划下一章、起草下一章、审稿、创建修订任务、应用修订和导出。
- `cli.py`：作家工作台入口，命令只负责解析参数、加载项目、调用 workflow，并输出简洁中文状态。

未来的 `NovelAgent` 应在 workflow 之上做决策：根据项目状态选择调用哪个 workflow，而不是把长期记忆和写作逻辑塞进一次自由文本调用。

## 数据模型

新增模型：

- `WorldRule`：世界观或类型规则，包含编号、说明、来源和状态。
- `TimelineEvent`：时间线事件，包含章节号、标题、摘要和涉及人物。
- `PlotThread`：线索或剧情线程，包含状态、相关章节和兑现说明。
- `ChapterPlan`：章节计划，包含章节号、标题、目标、场景、beats、需要引用的人物和线索。
- `RevisionTask`：修订任务，包含目标章节、问题类别、说明、严重级别和完成状态。

现有 `ChapterDraft` 保持兼容，但新增可选字段 `revision` 和 `source_plan_number`，用于区分初稿和修订版，并追踪来源计划。

## 工作流

`seed` 继续创建基础项目，同时初始化第一批世界规则、线索和时间线。

`plan_next_chapter` 根据已有章节数量和章节大纲生成下一章计划。如果已有计划未起草，则复用该计划，避免重复规划。

`draft_next_chapter` 找到第一个未起草的章节计划，生成章节草稿，追加时间线事件并保存项目。

`review_chapter` 检查未知人物、重复章节号、章节计划 beats 覆盖、线索引用和时间线基本顺序。

`create_revision_tasks` 把审稿报告中的问题转换成结构化修订任务。

`revise_chapter` 根据未完成修订任务生成修订版章节，标记任务完成，并重新审稿。

`export_manuscript` 按章节号导出正文，默认导出最新修订版；没有修订版时导出初稿。

## CLI

保留：

- `seed`

新增：

- `status --project <path>`：展示标题、章节数、计划数、未完成修订任务数。
- `plan-next --project <path>`：规划下一章。
- `draft-next --project <path>`：起草下一章。
- `review --project <path> --chapter <number>`：审稿指定章节。
- `revise --project <path> --chapter <number>`：根据修订任务生成修订版。
- `export --project <path> --out <path>`：导出正文。

CLI 错误使用中文提示，返回非零退出码。项目文件损坏、项目不存在、章节不存在、没有可起草计划都需要明确失败。

## 测试策略

使用 `unittest` 和临时目录覆盖：

- 新模型可保存和加载。
- 下一章规划不会重复创建同一章计划。
- 起草下一章会更新章节和时间线。
- 审稿能发现未知人物、缺失 beat、重复章节。
- 修订任务能由审稿报告创建并被修订流程完成。
- CLI 新命令能操作真实项目文件。
- 导出正文包含章节标题和正文。
