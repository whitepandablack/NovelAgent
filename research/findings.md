# 当前发现：NovelAgent 故事质量评测体系

## 当前理解

NovelAgent 的评测不能只问“这一章写得好不好”。长篇小说 agent 的关键能力是维护一个随章节变化的故事状态，包括人物目标、关系变化、世界规则、伏笔状态、时间线和修订历史。

因此，评测应当以“固定项目状态 + 明确创作动作 + 可验证状态变化”为基本单元。

## 初步突破方向

### 1. 把故事 eval 设计成状态回归测试

软件工程 benchmark 如 SWE-bench 的启发是：给定真实上下文和任务，模型产出 patch，然后用测试判断是否解决问题。迁移到小说创作，eval case 可以给定项目状态和创作任务，要求 agent 产出章节计划、草稿或修订版，再用规则和 judge 检查状态变化是否正确。

### 2. 用 narrative minimal pairs 测长篇记忆

NoCha 的方法适合改造成“设定真伪对”：给 agent 或 judge 两个很接近的叙事声明，只有一个符合项目状态。例如：

- 真：米拉知道震颤记录异常，但不能安全说出全部真相。
- 假：米拉第一次见到林澈时已经公开解释了震颤来源。

这能测 agent 是否记住长期故事事实，而不是只会写顺口文本。

### 3. 区分 beat mention 和 beat grounding

当前 NovelAgent 只检查 beat 字符串是否出现，这很容易被文本刷分。下一步应区分：

- mention：正文提到“矛盾记忆”
- grounding：通过具体场景、人物行动、线索变化呈现“矛盾记忆”

这可能成为 NovelAgent eval 的核心创新点之一。

### 4. 修订评测必须包含 non-regression

故事修订不是简单把问题补上。合格修订需要：

- 解决指定审稿问题
- 保留人物动机
- 不破坏时间线
- 不关闭未兑现伏笔
- 不引入未知人物或新规则冲突

这适合做成固定 regression eval。

## 待验证问题

- 如何把叙事质量拆成规则可测部分和 judge 可测部分？
- LLM-as-judge 是否会偏爱华丽文本而忽视故事状态？
- minimal-pair 评测能否覆盖“伏笔状态”和“人物弧线”？
- 是否应该把每个 eval case 都保存 expected_state_delta？
